# Single-Server Monitoring System

## 개요
- 단일 서버의 자원 상태(CPU, 메모리, 디스크, 네트워크 등)를 실시간으로 수집·시각화하는 경량 모니터링 시스템을 목표로 한다.
- 초기 버전에서는 단일 서버 환경에 집중하며, 추후 다수의 단일 모니터링 인스턴스를 통합하는 방향으로 확장한다.

## 핵심 기능 (v1)
- **에이전트**: 서버 자원 지표 수집 및 전송
- **수집기/저장소**: 수집된 메트릭을 저장하는 최소한의 스토리지 계층
- **API 레이어**: 모니터링 데이터 조회 및 알람 트리거
- **대시보드**: 실시간/히스토리컬 조회, 기본 알람 설정 UI

## 기술 스택 제안
- **에이전트**: Python 기반 lightweight collector (psutil 등 활용)
- **수집기**: FastAPI + TimescaleDB(or PostgreSQL) 기반
- **대시보드**: React + Recharts (또는 대안 시각화 라이브러리)
- **인프라**: Docker Compose로 단일 서버 배포

## 시스템 구조 (단일 서버 기준)
- `agent` → 주기적으로 `/metrics` 엔드포인트에 전송
- `collector` → 수신 후 DB 저장 및 알람 로직 수행
- `api` → 대시보드와 외부 자동화 시스템에 데이터 제공
- `dashboard` → API 연동을 통한 UI 표시

## 향후 확장 방향
- **멀티 서버 통합**: 여러 단일 서버 모니터링 인스턴스를 중앙 허브에서 집계
- **고가용성**: 수집기/DB 이중화, 메시지 큐 도입 고려
- **알람 고도화**: ML 기반 이상 징후 탐지, Slack/Email/Webhook 연동

## 제외된 항목
- 연구자 자원 요청 및 관리자 할당 플로우는 추후 범위로 이동하여 현재 버전에서는 다루지 않는다.
